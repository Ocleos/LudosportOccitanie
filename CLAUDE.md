# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Vitrine (showcase) site for Ludosport Occitanie, a sports association for lightsaber combat (Ludosport) in
Montpellier/Nîmes. All content is in French. Built with React 19 + TypeScript + Vite + Tailwind CSS v4, routed with
TanStack Router. Site content stays in French, but all developer-facing material (docs, config, comments, commit
messages) is in English.

## Audit

[AUDIT.md](AUDIT.md) is the project's living backlog: security vulnerabilities, technical improvements, and the
functional roadmap, each tagged with a priority (P0–P3), a time estimate, and the fix required. When an item from AUDIT.md
is fixed, update or remove its entry rather than letting the file drift out of sync with the codebase.

## Commands

Package manager is **Bun** (`bun.lock` is the committed lockfile).

- `bun install` — install dependencies
- `bun dev` — start the Vite dev server
- `bun run build` — generate the route tree (`tsr generate`), type-check (`tsc`), then build for production
  (`vite build`)
- `bun run preview` — preview the production build
- `bun run lint` — run Biome check with autofix (`biome check . --write`)
- `bun run format` — run Biome formatter (`biome format . --write`)

There is no test suite/runner configured in this project.

### Linting/formatting

Biome (`biome.json`) is the single source of truth for both lint and format — no ESLint/Prettier. Notable
non-default rules: `noConsole: warn`, `noUnusedVariables: error`, Tailwind class sorting via the `nursery.useSortedClasses`
rule, and import/attribute/key sorting assists enabled (`organizeImports`, `useSortedAttributes`, `useSortedKeys`, etc.).
Formatting: single quotes, semicolons, trailing commas, 2-space indent, 120 char line width. Run `bun run lint`
before committing — the pre-commit hook enforces a clean `biome ci` run, and `commit-msg` enforces Conventional
Commits via commitlint (`@commitlint/config-conventional`).

## Architecture

- **Routing**: [src/main.tsx](src/main.tsx) renders a single `<RouterProvider>` backed by
  [src/router.ts](src/router.ts) (TanStack Router, file-based). Routes live in `src/routes/`:
  [\_\_root.tsx](src/routes/__root.tsx) is the shared layout (`HeadContent`, skip link, `Navbar`, `<Outlet>`,
  `Footer`), and each sibling file (`index.tsx`, `le-sport.tsx`, `cours.tsx`, `cours-essai.tsx`, `evenements.tsx`,
  `contacts.tsx`) maps one URL to one top-level section component via `createFileRoute`, plus a `head` option (see
  the SEO bullet below). `src/routeTree.gen.ts` is generated by `tsr generate` (part of `bun run build`) — don't
  hand-edit it. There is no single long page anymore; navigation is real client-side routing, not anchor/scroll.
- Each top-level section component lives in `src/components/*.component.tsx` (or a feature subfolder) and is a
  self-contained `<section aria-labelledby=...>` with its own heading id — this pattern (semantic section + labelled
  heading) is used consistently for accessibility and should be followed for new sections/routes. Each route also has
  exactly one `<h1>` (see the `Title` bullet below).
- Feature subfolders group related components:
  - `src/components/presentation/` — the `/le-sport` page: `presentation.component.tsx` composes `PrinciplesInfo`,
    `PathInfo` (forms/weapons/learning-path table), `Gallery` (photo carousel) + `Lightbox` (fullscreen viewer), and
    `Videos`.
  - `src/components/places/` — the `/cours` page: `places.component.tsx` maps over `PLACES`/`COURSES` (from
    `src/data/`, see below) and renders `CourseInfo` (static info cards), `CourseCard` (one per weekly session) and
    `PlaceCard` (address + embedded Leaflet map, see below).
  - `src/components/events/` — `events.component.tsx` maps over `EVENTS` (from `src/data/events.ts`, see below),
    `eventCard.component.tsx` is the presentational card.
  - `src/components/navigation/` — `Navbar` (desktop links + CTA) and `MobileMenu` (full-screen dialog, rendered as a
    header sibling — see the comment in `navbar.component.tsx` for why), both driven by the shared `NAV_LINKS` list
    in `navLinks.ts`.
  - `src/components/ui/` — shared presentational primitives reused across sections: `Card`, `Title` (renders an
    `h2` by default — for sub-headings within a page — or an `h1` when passed `level='h1'`; each route uses `Title`
    with `level='h1'` exactly once for its own page title, except `/` ([home.component.tsx](src/components/home.component.tsx))
    and `/cours-essai` ([trialCourses.component.tsx](src/components/trialCourses.component.tsx)), which hand-roll
    their own `<h1>` instead of using `Title`), `LabelIcon`/`LabelLinkIcon` (icon + text, icon can be a
    `lucide-react` component or an SVG path masked via CSS `mask-image`), `MaskIcon`, `TrialCourseCta`, and
    `YoutubeVideo` (click-to-load `youtube-nocookie.com` embed, so no third-party cookies/JS load until the user
    opts in).
- `PlaceCard` ([placeCard.component.tsx](src/components/places/placeCard.component.tsx)) embeds a `leaflet` map
  (OpenStreetMap tiles, scroll-zoom disabled, custom pin `divIcon` using the theme's primary color) — the only
  non-trivial third-party integration outside the trial-course form.
- `TrialCourses` ([src/components/trialCourses.component.tsx](src/components/trialCourses.component.tsx)), the
  `/cours-essai` page, is the one interactive/stateful component: a controlled form that POSTs JSON to
  [api/trial-course.ts](api/trial-course.ts), a Vercel Edge Function that relays to FormSubmit. The real FormSubmit
  endpoint/CC addresses live in server-only env vars (`FORM_SUBMIT_ENDPOINT`, `FORM_SUBMIT_CC` — comma-separated, see
  `.env.local`) — deliberately **not** `VITE_`-prefixed, since `VITE_*` vars are inlined in plain text into the
  shipped client bundle. The client sends the honeypot (`website`) field and the time-on-page timestamp (`openedAt`)
  along with the form data, and the Edge Function re-checks both server-side (plus required-field/email/age
  validation and a same-origin check) before relaying to FormSubmit — this closes the direct-`curl`-to-FormSubmit
  bypass a client-only check can't prevent. Follow this pattern (proxy through `api/`, keep secrets un-prefixed) for
  any other form added later.
- **Content data**: `src/data/` holds typed data modules that components map over, keeping content separate from
  markup — `places.ts` exports the `PLACES` lookup (id/name/logo/address/accesses/latitude/longitude per venue) and
  the `Place` type; `courses.ts` exports the `COURSES` array (each entry referencing a `Place` plus a `school` of
  `'montpellier' | 'nimes'` — the founding school/`/cours` heading it's grouped under, which isn't always the same as
  the venue: the "Nîmes" heading covers both the Nîmes and Caissargues venues) and the `Course` type; `events.ts`
  exports the `EVENTS` array and the `EventItem` type. Update schedules/venues/events by editing these files, not the
  components.
  `CourseCard`/`EventCard` import their prop types directly from `Course`/`EventItem` rather than redeclaring them.
- `src/utils/format.utils.ts` wraps `dayjs` (locale set to `fr` in `main.tsx`) with named format constants
  (`FORMAT_FULL_DATE`, etc.) — use `formatDate(value, FORMAT_*)` rather than calling `dayjs` directly, for
  consistent French date formatting (used by `EventCard`).
- No global state management or data-fetching library — state is local `useState`/`useMemo` per component.
- Styling is Tailwind v4 using the CSS-first config in [src/index.css](src/index.css) (`@theme` block), not a
  `tailwind.config.js`. Custom theme tokens: `--color-primary`/`-dark`/`-light`, custom fonts `--font-neo` /
  `--font-neo-bold` (self-hosted NeoSansPro TTFs in `public/fonts`, loaded via `@font-face`), a custom
  `--aspect-video-short` ratio (for `YoutubeVideo`'s short/vertical mode), and an `xs` breakpoint. Prefer these
  tokens (`bg-primary`, `font-neo-bold`, etc.) over ad hoc values. Tailwind v4's extended palette (e.g. `taupe`) is
  available on top of the custom tokens.
- Icons come from `lucide-react`. Static images/SVGs live under `src/assets/` (including `assets/icons/` and
  `assets/photos/`, the latter shipping paired full-size/`-thumb` webp images for the gallery); files served as-is
  (fonts, `logo.svg`, favicons, `manifest.json`, `robots.txt`, `sitemap.xml`) live under `public/`.
- **SEO/meta tags**: `<title>`, meta description, canonical URL, and the `og:title`/`og:description`/`twitter:title`/
  `twitter:description` pairs are set per route via TanStack Router's `head` route option — `buildPageHead`
  ([src/utils/seo.utils.ts](src/utils/seo.utils.ts)) builds the tag list from a `{ title, description, path }` input,
  and every `src/routes/*.tsx` file (including `__root.tsx` as the site-wide default) calls it with route-specific
  copy. `HeadContent` (rendered in `__root.tsx`) turns that into real `<title>`/`<meta>`/`<link>` elements that React
  19 hoists into `document.head`, ahead of any static tag with the same purpose. [index.html](index.html) itself only
  hardcodes what's genuinely identical across every route — charset/viewport, `keywords`/`robots`/`theme-color`,
  `og:type`/`og:locale`/`og:image`(+dimensions), `twitter:card`/`twitter:image`, favicons/manifest, and a fallback
  `<title>` (kept because React inserts its own title *before* it, so it's always superseded once JS mounts, but
  still correct for the very first paint or for a crawler that never runs JS) — plus the JSON-LD `SportsOrganization`
  schema (org-level, not page-specific, so it stays static). Add a new route's SEO copy by calling `buildPageHead` in
  its route file; don't add per-route tags to `index.html`. Note: a crawler that doesn't execute JavaScript (e.g.
  Facebook's/Twitter's link-preview bots) still only ever sees `index.html`'s static fallback, so social-link
  previews are only fully accurate for `/` — fixing that for every route would need SSR/prerendering, out of scope
  here. [public/sitemap.xml](public/sitemap.xml) lists all 6 routes and should gain an entry whenever a route is
  added.
- [vercel.json](vercel.json) sets security headers (CSP, HSTS, `X-Frame-Options`, `Permissions-Policy`, etc.) on
  every response. The CSP's `script-src` allow-lists the inline JSON-LD `<script>` in `index.html` by its sha256
  hash — if you edit that block, recompute the hash (command in the comment above it in `index.html`) and update
  `vercel.json` accordingly. `img-src` is scoped to the specific third-party hosts actually used (YouTube
  thumbnails, OpenStreetMap tiles) — extend it if a new image host is added.
- Path alias `src/*` is configured in `tsconfig.json` for absolute-style imports from `src/` (existing code mixes
  this with relative `../` imports — either is fine, prefer whichever matches the surrounding file).
